| 1 | B          | `common/outbox.py`: the outbox retry selected rows with `created_at < NOW(3) - INTERVAL 2 SECOND`, while `created_at` was written as Europe/Zurich local time.                         | The database clock runs in UTC: rows would have been retried only an hour or more late (or, with the opposite offset, at once), so the gap in the sales report after a reporting outage would not close within seconds as the design says.                                             | code review (the agent re-read its own code before the first run) | cut-off computed in Python in the same time zone, before the first commit of `variant B v1` |
| 2 | B          | `common/client.py`: the 2 s timeout of a call between services was only the httpx timeout.                                                                                             | Docker's DNS takes about 4 s to fail for a stopped container, and the lookup is outside the httpx timeout. With customers stopped, a checkout with a customer (earn + undo) took more than 10 s and the client timed out, instead of `503` within 4 s as in the design (2 s per call). | other: manual outage check (customers stopped, timed checkout)    | the name is resolved with its own deadline inside the 2 s budget; decision 12 in `docs/design.md`; in `variant B v1` |
| 3 | bench (C4) | `bench/personal_data.sh` searched the raw database dump with `grep -i`.                                                                                                                | Git Bash's grep crashes (core dump) on the very long `INSERT` lines of a dump, so every store reported 0 terms: the C4 metric would have shown no personal data even in the monolith.                                                                                                  | measurement (test run against baseline gave 0 instead of 1 store) | the dump is lowercased and split at commas before a plain `grep -F`; in `bench: personal-data scan for C4` |
